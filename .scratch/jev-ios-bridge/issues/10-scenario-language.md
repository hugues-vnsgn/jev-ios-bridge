# Scenario language: goals, assertions, typed values

Type: grilling
Status: resolved
Blocked by: 21

## Question

How does a developer, or Claude on their behalf, write a scenario? Decide:

- **The minimal schema:**
  - goal text;
  - assertions;
  - values to type;
  - preconditions, such as a test account or seeded data.
- **Typed values.** Jev cannot write text, so every value is a literal or a named value in the scenario. Only US-keyboard characters can be typed, so accented text, such as Vietnamese, needs another input path or is out of v1.
- **Assertion phrasing.** How an assertion is worded so it becomes one clean Noul question. Also whether ordering, as in "after login, the Home tab is visible", is in v1.
- **Where reusable scenarios live.** Files in the app's repo keep later unattended runs possible.
- **Who writes what.** Decide what Claude writes and what a person reviews. TypeSafe notes that coding agents tend to write weak questions.

## Answer

The public v0.1 contract is an explicit script: app bundle ID, optional dedicated device UUID, descriptive setup preconditions, a map of literal typed values, and 1–100 ordered steps with unique IDs. Steps are guarded tap/full-field replacement/directed swipe actions, bounded waits, or assertion checkpoints. The final step must be a checkpoint. Reject legacy goal-only/autonomous-checkpoint input at public entrypoints.

Selectors use exact identifier, role, label and value predicates with at least one nonblank identity field. An empty value is a valid filter. Guards require distinguishing visible anchors and may forbid other anchors; target uniqueness and known visibility/eligibility are mandatory. Assertions describe observable current-screen facts, not inferred backend persistence. Each checkpoint has 1–20 uniquely named claims and uses the fixed Noul template. Ordered checkpoints prove successive screens; no later screen retrospectively proves an earlier claim.

Typed values are supplied by the author, never generated by Jev: at most 32, each at most 2,048 printable US-keyboard characters, with leading hyphens rejected for the pinned vendor limitation. Preconditions may seed persistent data but cannot preserve navigation across app restart. Store reusable JSON in the consuming app repo, e.g. `scenarios/ios/`; keep real secrets out of committed fixtures. The host/developer authors the script up front and reviews guards and claims. See the [scripted schema and authoring plan](../scripted-production-plan.md).
