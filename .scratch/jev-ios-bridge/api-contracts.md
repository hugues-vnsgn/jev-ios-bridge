## Jev request, answer and cancellation

The published `0.6.0` API is `new TypeSafeClient({ defaultModel?: string, timeout?: number, retry?: Partial<RetryPolicy> })`, then `client.systemOne({ state, questions, model? }, { signal?, timeout?, retry? })`. The client reads `TYPESAFE_API_KEY` from the environment; its default model is the moving `jev-latest` alias. Set `model: "jev-1.13.0"` or `defaultModel: "jev-1.13.0"` for reproducible evaluation. The HTTP body sent to `POST /v1/systemone` contains `model`, `state` and named `questions`; it has no image, session or streaming field. [SDK guide](https://docs.typesafe.ai/sdk/javascript), [client reference](https://docs.typesafe.ai/sdk/javascript/api/classes/TypeSafeClient), [models](https://docs.typesafe.ai/models), [HTTP API](https://docs.typesafe.ai/api).

The helpers are `choice(instructions, criteriaObject)`, `noul(instructions, optionalTrueFalseCriteria)` and `score(instructions, criteriaArray)`. For a step decision, a Choice's criterion keys should be stable action IDs, with any required action parameters in the corresponding description or state. The response is `result.answers[id]`: Choice exposes `choice`, `confidence` and `probabilities`; Noul exposes `noul` (probability of yes) and **no confidence**; Score exposes `score`, `confidence`, `legend` and `probabilities`. The result also has `model` and `usage.input_tokens`/`usage.output_tokens`. Question IDs map answers but do not influence inference. [SDK types](https://github.com/typesafe-ai/typesafe-sdk-js/blob/v0.6.0/src/types.ts), [result reference](https://docs.typesafe.ai/sdk/javascript/api/interfaces/SystemOneResult), [API answer shapes](https://docs.typesafe.ai/api).

Pass the run's `AbortSignal` in the second argument, for example `client.systemOne(request, { signal })`; cancellation applies to the in-flight attempt **and pending retries** and rejects as `APIUserAbortError`. A timeout is per attempt, not a total request budget. Defaults are 10 s per attempt and two retries for 408, 429, 5xx, connection failures and timeouts; set a run-level deadline separately. Keep SDK `logLevel` below `debug` when state may hold private screen text, since debug logs bodies. [request options](https://docs.typesafe.ai/sdk/javascript/api/interfaces/RequestOptions), [SDK 0.6.0 client source](https://github.com/typesafe-ai/typesafe-sdk-js/blob/v0.6.0/src/client.ts), [retry reference](https://docs.typesafe.ai/sdk/javascript/api/interfaces/RetryPolicy).

Jev 1.13 accepts text or structured text state, with a 64k total request budget and a separate 32k limit for state plus the longest question. The model cannot interpret a screenshot directly or produce arbitrary text to type into the app. [models](https://docs.typesafe.ai/models), [state](https://docs.typesafe.ai/concepts/state).

## MCP v2 server seam

Use `McpServer` from `@modelcontextprotocol/server`, `serveStdio` from `@modelcontextprotocol/server/stdio`, and `server.registerTool(name, { inputSchema: z.object(...), outputSchema?: z.object(...) }, async (args, ctx) => ...)`. `serveStdio(() => server)` handles both current and legacy protocol openings by default; a hand-wired `server.connect(new StdioServerTransport())` serves the 2025 protocol era only. Tool cancellation is `ctx.mcpReq.signal`, which can feed Jev's `{ signal }` option and child-process cancellation. A tool with `outputSchema` should return `structuredContent` matching that schema as well as readable `content`. Keep stdout exclusive to MCP frames; send diagnostics to stderr. [v2 overview](https://ts.sdk.modelcontextprotocol.io/v2/), [stdio guide](https://ts.sdk.modelcontextprotocol.io/v2/serving/stdio), [protocol versions](https://ts.sdk.modelcontextprotocol.io/v2/protocol-versions), [v2 migration guide](https://ts.sdk.modelcontextprotocol.io/v2/migration/upgrade-to-v2), [server tools](https://ts.sdk.modelcontextprotocol.io/v2/servers/tools).

## MobileBuildMCP CLI contract

Help from the published 2.7.1 binary confirms the read command is `mobilebuildmcp ui-automation snapshot-ui --simulator-id <UUID> --output json`; add `--verbose` for full data. A configured session default can supply the simulator ID. `--output` accepts `text|json|jsonl|raw`, and `--json '<object>'` is an alternate tool-argument input. The CLI writes one JSON envelope on stdout with `schema`, `schemaVersion`, `didError`, `error`, `data` and optional `nextSteps`; it sets a nonzero exit code when `didError` is true. Parse the envelope even on nonzero exit to retain the structured error. [published 2.7.1 tarball](https://registry.npmjs.org/mobilebuildmcp/-/mobilebuildmcp-2.7.1.tgz) (`build/cli/register-tool-commands.js`, `manifests/tools/snapshot_ui.yaml`), [capture schema](https://raw.githubusercontent.com/getsentry/MobileBuildMCP/v2.7.1/schemas/structured-output/mobilebuildmcp.output.capture-result/2.schema.json).

For `snapshot-ui`, the envelope schema is `mobilebuildmcp.output.capture-result`, version `2`, and the payload sits at `data.capture`. Default compact capture has `type: "runtime-snapshot"`, `rs: "1"`, `screenHash`, `seq`, `count`, `targets`, `scroll`, optional `text`, and `udid`. Each target row is a pipe-separated `ref|action|role|label|value|identifier`; compact `targets` are capped at 64 and selected from actionable elements, while `scroll` is capped at 32. Full `--verbose` capture instead has `protocol: "rs/1"`, `simulatorId`, `capturedAtMs`, `expiresAtMs`, `elements[]` and `actions[]`; each element includes its own `ref`, identity and action data. Treat these as two different shapes under the same envelope, rather than expecting `data.capture.elements` in compact mode. [capture schema](https://raw.githubusercontent.com/getsentry/MobileBuildMCP/v2.7.1/schemas/structured-output/mobilebuildmcp.output.capture-result/2.schema.json), [published CLI formatter](https://registry.npmjs.org/mobilebuildmcp/-/mobilebuildmcp-2.7.1.tgz) (`build/utils/structured-output-envelope.js`).

The tap command is `mobilebuildmcp ui-automation tap --simulator-id <UUID> --element-ref <ref> --output json`. UI tools are stateful and route through a per-workspace daemon, so snapshot and action calls must use the same workspace and version. References belong to the latest runtime snapshot for that simulator, expire after 60 seconds, and need refreshing after navigation or other screen changes. `--since-screen-hash` may return a `runtime-snapshot-unchanged` capture without elements. [published CLI help and source](https://registry.npmjs.org/mobilebuildmcp/-/mobilebuildmcp-2.7.1.tgz) (`build/mcp/tools/ui-automation/shared/snapshot-ui-state.js`, `build/mcp/tools/ui-automation/snapshot_ui.js`), [tap manifest](https://github.com/getsentry/MobileBuildMCP/blob/v2.7.1/manifests/tools/tap.yaml).
