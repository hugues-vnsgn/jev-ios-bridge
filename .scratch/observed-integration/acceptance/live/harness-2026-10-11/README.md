# Public-interface live recorder — disabled, unexecuted

This successor implements an initial source-only recorder/controller for independent review. No JavaScript here has been executed, syntax-checked or tested. `dispatch.json` deliberately cannot enable it: review, runtime identity, environments, source/build pins, metadata list, protocol version and rows are unset. Product, target apps and the historical disabled draft remain unchanged. Only the sole operator may execute after Root accepts storage, builds, the corrected L04 oracle and this harness.

**Correction revision, still unreviewed:** the first independent reviews found staged-plist ordering, eager legacy credential checks, missing readiness approval, missing CLI exit checks and undrained public pipes. Staging now binds before creation; CLI exits are checked; public pipes are drained; a Root readiness barrier is implemented. Both CLI `run` and MCP `start_scenario` require judge construction before admission. Root selected the narrow real-key legacy-only exception in `legacy-exception.md`; it has a separate disabled approval field. No key has been read during implementation.

## Components

- `controller.mjs`: serial public CLI/MCP orchestration, public process receipts, request files, MCP transcripts, terminal oracles, cross-process retrieval and L04 identical/conflicting requests. Legacy-only public CLI successor uses a separate guard and exact DEVICE_BUSY/exit2 oracle.
- `legacy-bootstrap.mjs` / `legacy-guard.mjs`: sequential common recorder then outbound-denial guard then explicit original-file credential load; no key serialization/hash, no observed-process credential access, one existing loopback watch listener only. Both recorder and outbound counters must remain zero on the refused successor.
- `readiness-barrier.mjs`: bounded persisted-readiness inspection, initial-selector check, and exact Root acceptance binding before each action. It writes a checkpoint, then waits at most240s and no later than15s before a conservative300s parked-TTL cutoff derived from readiness file persistence. Root writes `root-readiness-acceptance.json` with the exact checkpoint binding and status `ROOT_ACCEPTED`. Binding includes dispatch, preparation/action, app provenance/accepted artifact manifest, device/allocation, and both readiness file hashes. The approval is a coordinator audit, not an owner prompt. No approval/late approval means stop and retain the allocation.
- `process-preload.mjs`: explicit parent-only `--import`; patches exported `spawn` and callback `execFile`, then synchronizes ESM builtin bindings before production entry. Other child APIs refuse. Uses unchanged real production CLI/composition; no fake backend or direct store writes.
- `command-policy.mjs`: finite exact metadata commands and narrow create/staged-plist/provider forms. Create's successful output binds fresh device identity. Staged metadata binds install path. Latest full action snapshot binds the unique visible/enabled touch target. Input is limited to one touch for L01/L04/L05 and zero for L02/L03. Silent phases deny every child.
- `receipts.mjs`: exclusive private raw files, durable close receipts, bounded retention, shared stop marker. Child pipe `push` is wrapped before stream decoding to preserve original bytes without changing flowing state or consuming data. Original `push` arguments/receiver/return are preserved.
- `l04-callback-decision.mjs`: requires retained successful raw touch output and actual exit0/null-signal close, then supplies one synthetic non-ABORT error and **empty output** to the original callback. It never updates admission.

## Intended limits

Current disabled template: 420s/public process, 16MiB/public output; 130s/direct child, 8MiB combined child output; 1200 direct children/process; 1000 metadata commands/preparation; 160 measured vendor listings/preparation; 31 snapshot/screenshot pairs/preparation; 102 pairs/action; 380s/RPC; 10s EOF close; TERM then 1s KILL escalation for child time/output exhaustion. These are harness ceilings, not altered product budgets or acceptance counts. Product preparation360s/action10s remain unchanged. Unexpected commands or exhausted recorder budgets close future dispatch and stop the batch.

Preparation and action use separate real MCP processes even in MCP→MCP rows. Parked ownership survives preparation process exit under the accepted contract. This avoids injecting phase-transition signals into the production process. Public action polling uses `get_observed_action`, never replay. MCP EOF follows completed responses; timeout is failure, not evidence of settlement. Descendant settlement remains explicitly unobserved.

## L04 and successor

Expected public flags are **null/null**, `inconclusive/UI_ACTION_UNCONFIRMED`, committed quarantine. Raw recorder bytes separately demonstrate a successful actual backend touch. See existing `tests/observed-service.test.ts` lost-input-reply case and `public-contract.md` nullable flag semantics. Do not synthesize true/false ledger flags or manufacture an acknowledgement. Normal callbacks are also held through actual close and durable evidence flush; this adds disclosed latency within product deadlines. L04 alone changes the bytes/error.

The legacy successor script is version1 with fixture bundle, explicit quarantined device, empty values and one100ms wait for home.heading, without model assertions. Source inspection established both public paths eagerly require a judge credential. The separately approved exception loads only TYPESAFE_API_KEY from the fixed original `.env`, inside the legacy child after outbound denials are installed. It does not hash, dump or copy the file/key into evidence. Required result is public DEVICE_BUSY in prepare, inconclusive verdict, exit2, zero steps/tokens, zero outbound attempts and zero backend attempts, with actual close and guard receipts. Authentication failure or a recorder-denied backend attempt is not admission proof. This covers credential-loaded admission, not authenticated API behavior.

## Proof boundaries / unfinished acceptance

Root must inspect actual V/R/N, all child and public closes, callback parity, one L04 injection and raw success, immutable retrieval/conflict results, zero backend successor calls, snapshots/JPEGs and terminal exports.
