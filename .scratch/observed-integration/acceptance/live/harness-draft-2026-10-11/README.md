## Raw receipts and callback ordering

For each admitted direct child reserve an exclusive sequence/receipt path before launch; record executable/argv/cwd, safe environment keys/hash, operation phase and row. Preserve stdout/stderr as raw bytes, start, spawn/error/exit/signal events, and actual `close` independently of promise/callback completion. Use finite byte/time bounds fixed by dispatch; any overflow, failed retention, missing close or unexpected child closes the harness's future-dispatch gate and leaves the attempt uncertain. Preserve production cancellation/kill behavior; recorder failure is not permission for device cleanup. A parent exit or sent signal does not prove descendant settlement. Never invent successful close from `execFile` callback alone.

Avoid mutating child streams, signal options, result bytes, errors or timing except for the explicitly declared L04 injection. Adding data listeners can change flowing state; establish listener installation before consumers and audit byte equality. Recording raw bytes asynchronously introduces a barrier before claims of durable retention. A delay to flush evidence must be disclosed and stay within production deadlines. If recording fails, do not invoke a synthetic success or execute replacement work.

For L04 retain the actual successful touch output and actual exit0/null-signal close, then suppress the result at the execFile callback boundary before the production driver's promise resolves and parser acknowledges. Hold the callback only until actual close and retained raw receipt are proven; do not add captures at this boundary. Apply once to the exact row/action/device/element command. The candidate pure module mirrors only the current success envelope shape needed to qualify injection; production parsing remains authoritative for normal operation. It expects upstream cryptographic byte verification and durable retention; its boolean/hash fields are not themselves proof.

**Critical detail:** passing successful stdout with a synthetic callback error can still produce `terminalAcknowledged=true` in `parseEnvelope`. The callback presented to production must withhold the successful bytes as well, while the evidence keeps them intact. The draft returns a fixed non-ABORT error and empty output so the driver cannot parse an acknowledgement. Before use, review propagation to the required committed `UI_ACTION_UNCONFIRMED` result; this has not been executed or verified. Every failed precondition of the decision means stop without claiming the L04 oracle, not retrying the touch.
