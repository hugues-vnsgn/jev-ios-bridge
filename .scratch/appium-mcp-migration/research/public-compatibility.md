# Public Appium compatibility boundaries

Researched 2026-10-14 against bridge base `2f9ba8d4b` and the installed candidate: `appium-mcp@1.97.0`, XCUITest `12.17.1`, UiAutomator2 `8.7.0`, its nested Android driver `14.2.0`. Research only; no vendor execution, device operation, tests, or credential access. Hindsight search returned an empty initiative page and contributed no facts.

## Answer and evidence level

The candidate has public Appium APIs for the required UI operations. Preserving the bridge requires a small versioned core extension, a complete XML normalizer, bridge-owned action/lifecycle policy, and the native helpers permitted by ADR-0010/0011. MCP tool success, session deletion, and source support do not prove native fencing or live behavioral compatibility. This report makes no new live claim. Preserve the migration spec's corpus, replacement-device and mode gates.

Source notation below: `M:` is `node_modules/appium-mcp/`; `X:` is `node_modules/appium-xcuitest-driver/`; `U:` is `node_modules/appium-uiautomator2-driver/`; `A:` is `U:node_modules/appium-android-driver/`. These were read from the ignored candidate installation under the planning worktree's `.scratch/appium-mcp-migration/candidate-stack/`. Exact graph remains in its `package-lock.json`; a wrapper pin alone does not freeze it. Bridge paths are relative to this report's checkout.

## Public seams

`M:package.json#exports` exposes `appium-mcp/core`, not `command.ts`, `session-store.ts`, or tool-handler subpaths. `M:src/core.ts` exports `createAppiumMcpServer`, `AppiumMcpCore`, `McpRegistry`, plugin types and policy. `M:src/plugin.ts#AppiumMcpCore` supplies `getDriver(sessionId)`, `getSessionInfo(sessionId)`, and `listSessions()`; plugins register tools and have `beforeCall`, `afterCall`, and `destroy` hooks. Use that public core to obtain the explicitly owned driver and invoke its public driver methods; do not import the internal wrappers inspected below. Core inventory describes sessions tracked by this process, not every native process or foreign automation. [Pinned core](https://github.com/appium/appium-mcp/blob/v1.97.0/src/core.ts), [plugin implementation](https://github.com/appium/appium-mcp/blob/v1.97.0/src/plugin.ts).

Create sessions through the public `appium_session_management` tool with explicit platform, device capabilities and session IDs on subsequent calls. `M:src/tools/session/session.ts` takes capabilities as a JSON string. Its `create-session.ts` merges ambient `CAPABILITIES_CONFIG` with defaults and supplied capabilities. Supplied capabilities win; local driver creation enables relaxed security. Thus the bridge must validate capabilities and restrict its registered tools/extension commands. The extension should expose typed results for XML, all-match lookup, launch, replacement/shown values, action acknowledgement and owned session inventory. Source-reading internal functions establishes behavior, not permission to import them. [Session tool](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/session/session.ts), [creation](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/session/create-session.ts).

## Operation mapping

| Existing behavior | Candidate source support and required adapter work |
| --- | --- |
| iOS restart with `app.launchArgs` | `X:lib/execute-method-map.ts` exposes `mobile: launchApp` with `bundleId`, `arguments`, `environment`; `X:lib/commands/app-management.ts#mobileLaunchApp` forwards the argument array to WDA. Arguments are ignored when the app is already running. Explicitly terminate then launch once; preserve installed app/data and already-booted prerequisites. `processArguments` is also a capability (`X:lib/desired-caps.ts`), but controlled extension launch makes ordering explicit. MCP `appium_app_lifecycle activate` has no launch-arguments input. [Pinned launch source](https://github.com/appium/appium-xcuitest-driver/blob/v12.17.1/lib/commands/app-management.ts). |
| Android restart/activity/string intent extras | `A:lib/execute-method-map.ts` exposes `mobile: startActivity`; `A:lib/commands/intent.ts#mobileStartActivity` accepts `component`, `wait`, `stop`, `extras`. Encode each existing string extra as `['s', key, value]`; `parseIntentSpec` converts that type to `--es`. Explicit `wait=true`, `stop=true` preserves force-stop/start intent. Validate returned Activity Manager output, because the method returns shell text. Resolve the launcher when activity is absent. Capability `optionalIntentArguments` exists but is a command-string encoding; prefer the structured public execute method. MCP activation has no activity/extras input. [Pinned intent implementation](https://github.com/appium/appium-android-driver/blob/v14.2.0/lib/commands/intent.ts), bridge `src/device/android/driver.ts#launch/#restart`. |
| Complete observation/all-match targeting | MCP `appium_get_page_source` gets current XML; `appium_find_elements` returns JSON `{elements:[{elementId,attributes?}]}`, including zero/all matches. Public driver `getPageSource`, `findElements`, `getAttribute`, `getElementRect` provide extension equivalents (`M:src/command.ts` demonstrates signatures). Normalize XML to bridge roles, identifiers, labels, values, placeholder, state, frames and capability flags; issue bridge snapshot-scoped refs, retain duplicate nodes, and apply `src/scripted/select.ts` uniqueness/guards before input. XML paths do not themselves supply stable element IDs; locate/rematch all candidates and reject ambiguity. [All-match tool](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/interactions/find-elements.ts), [source tool](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/interactions/get-page-source.ts). |
| Replacement text and shown value | MCP `appium_set_value` calls `setValue` without a clear and embeds literal text in success/error prose (`M:src/tools/interactions/set-value.ts`). It does not guarantee replacement or safe reporting. Extension: iOS public `clear(elementId)` then `setValue(text,elementId)`; Android `execute('mobile: replaceElementValue', {elementId,text})`, which sends `replace:true`. Read the same field's fresh value/text after settling; preserve `ActOutcome.shownValue`, allow transformed values, and omit it when field correspondence is uncertain. Empty, Unicode Android, secure and formatted fields need live proof. Preserve existing iOS value validation for this cutover. [iOS element methods](https://github.com/appium/appium-xcuitest-driver/blob/v12.17.1/lib/commands/element.ts), [Android replacement](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.0/lib/commands/element.ts), bridge `src/device/android/driver.ts#typedFieldIn/#actIssued`. |
| Tap, swipe, back, scroll | MCP `appium_gesture` supports element/point taps and swipe/scroll; `appium_perform_actions` exposes W3C sequences. `M:src/tools/gestures/handlers/swipe-scroll.ts` uses different direction conventions and can retry iOS input through alternate methods after an error. For bridge dispatch-once semantics, prefer explicit W3C actions via extension/perform-actions and preserve geometry/timing in the spec. Android Back is public `appium_mobile_press_key key=BACK`/driver `mobilePressKey(4,...)`. iOS Back stays the selected navigation button or an explicit left-edge swipe; it is not an iOS hardware Back. Preserve largest-scrollable versus screen-middle action-path evidence. [Gesture implementation](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/gestures/handlers/swipe-scroll.ts), bridge `src/device/index.ts#backButtonOf/#largestScrollable/#scrollFinger`, Android `#swipeWithin`. |
| Screenshot-coordinate tap and observed single tap | Driver `getScreenshot` returns PNG; `getWindowRect` plus orientation establishes action coordinates. MCP screenshot may resize (`maxWidth`); decode actual image dimensions and map only the guarded snapshot's screenshot using `src/device/index.ts#screenPointOf`. W3C point tap replaces AXe. Validate freshness, orientation, origin/insets and bounds on two sizes; wrapper comments alone do not prove coordinate units. Observed iOS single tap can use one explicit pointer sequence with a hold; no retry after uncertain mutation. Preserve current public iOS driven coordinate refusal. [Tap source](https://github.com/appium/appium-mcp/blob/v1.97.0/src/tools/gestures/handlers/tap.ts), `M:src/tools/interactions/screenshot.ts`, bridge `src/device/index.ts#tapOnce`. |
| Android `start=attach` and key-free capture | Bridge attach means operate the already-foreground app, not adopt another tool's Appium session. MCP `action=attach` requires a remote server/session and is outside this migration's scope (`M:src/tools/session/attach-session.ts`). Create an owned local session with explicit no-launch/no-reset/no-termination settings; check foreground identity through public current-package/activity/state methods. Preserve `APP_NOT_IN_FOREGROUND`. Capture creates no app launch/reset/stop, log stream, screenshot or Jev request; prints only after safe close. Pin `autoLaunch=false`, `noReset=true`, `forceAppLaunch=false`, `shouldTerminateApp=false` and audit session deletion side effects. This is source-supported but unproven on replacement devices. `U:README.md` capability table; bridge `src/capture.ts`, Android `#captureIssued/#checkForeground`. [UiAutomator2 capability docs](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.0/README.md). |
| App logs, health, presentation | Public app lifecycle `query_state` exposes states 0 through 4, not causal crash/ANR attribution. Inspected MCP tools do not replace app prints, filtered platform logs or the existing exit watcher. Retain read-only native log/crash observers, bounded late-event attribution, unavailable-versus-empty status, masked tails/pane, expected-shutdown suppression and owned stream cleanup. Simulator window presentation remains a native helper after boot-state validation. Sources: `src/device/android/logcat.ts`, `exit-watch.ts`, `src/device/index.ts#appProblem/#simulatorWindowCommand`, ADR-0010. |
| Cleanup/recovery/allocation lifecycle | Public session delete calls `driver.deleteSession()` then removes process-local inventory (`M:src/session-store.ts#safeDeleteSession`); it is not a native stop receipt. On disconnect, `M:src/create-server.ts` defaults to deleting owned sessions unless configured otherwise. Bridge durable dispatch closure, command settlement/fencing, native component identity and verification must govern lease release. Retain quarantine on uncertainty. Observe/prepare factories and capture must share admission. Bounded fresh-simulator creation/install/boot survives ADR-0009; parked preparation/action transfer must preserve ownership without accidental restart or stop. Normal cleanup does not erase phones/delete retained allocations. ADR-0011 and `src/device/admission*.ts`; [session deletion source](https://github.com/appium/appium-mcp/blob/v1.97.0/src/session-store.ts). |

## Observation limits requiring explicit decisions

Raw XML is required; locator summaries are not an assertion observation. `M:src/tools/session/create-session.ts#buildIOSCapabilities` defaults `pageSourceExcludedAttributes='visible,accessible'`. Override it so visibility survives. `X:lib/commands/source.ts#getPageSource` reads that setting. Android `U:README.md#settings-api` documents hierarchy compression, single-window default, and finite `snapshotMaxDepth`; configure and record them. A returned XML tree is not proof that all relevant nodes were captured. Define detectable overflow/truncation and fail safely; do not equate an absent vendor flag with completeness. Both assertion corpora must pass through this normalizer.

Preserve bridge `src/device/android/mapping.ts` distinctions: resource ID, content description versus text, field hint/placeholder, password handling, visible/enabled/selected/focused state, scrollability, label lifting and unselectable child text. Appium-specific correspondence and any tap-alias collapse need evidence; do not inherit MobileBuildMCP alias authorization. Source docs: [Android settings](https://github.com/appium/appium-uiautomator2-driver/blob/v8.7.0/README.md), [iOS source](https://github.com/appium/appium-xcuitest-driver/blob/v12.17.1/lib/commands/source.ts). XML/screenshots remain separate captures; preserve bounded settling and "screen still changing."

## Inputs the cutover must preserve

Owner direction: optional explicit named profile plus project default; existing scripts/options remain valid. Profile selection is new and absent from current schemas. It selects validated stack configuration and cannot silently override an authored device/app or expose a backend selector.

| Existing input | Current meaning/source |
| --- | --- |
| iOS device | `device.udid` → `JEV_DEVICE_UDID` → project `.mobilebuildmcp/config.yaml` `simulatorId`; UUID only, uppercased; no `booted` alias/automatic choice. `src/device/index.ts#configuredUdid/#selectDeviceId`. Current file has `schemaVersion:1`, `sentryDisabled:true`, `sessionDefaults.simulatorId`. Its reader extracts the `simulatorId` line directly. |
| Android device | Script `device.serial` or `device.avd` → `JEV_ANDROID_DEVICE`; no project config/any-device fallback. AVD resolves to stable AVD identity; emulator serial is not stable identity. `#selectAndroidDeviceName`, Android `#resolveDevice`. Capture keeps `--serial` → `--avd` → environment; both supplied flags are validated. `src/capture.ts#namedDevice`. |
| Scripts and launch options | Versions 1/2 and absent platform default to iOS as currently parsed; existing app/device/value fields, iOS argument limits and Android string-extra limits survive. Version 2 attach remains Android only; current iOS attach and driven point-tap refusals remain explicit. `src/scripted/schema.ts`, `contracts.ts`, `src/driven/policy.ts`, migration spec. |
| CLI/MCP | Retain run/report/logs/capture/mcp and observed commands, JSON/limit/wait/presentation options and exit/signal meanings. Keep `start_scenario`, `get_report`, `cancel_run`, optional `resolve_step`, and observed allocation/action tools with their schemas/replies. `src/cli.ts`, `src/mcp/index.ts`, `src/mcp/observed.ts`. Profiles must be additive optional inputs across applicable routes. |
| Environment/project/plugin | Keep `JEV_PROJECT_DIR`, `JEV_RUNS_DIR`, device defaults, log-pane/window switches, experimental gates, `.jev/config.json` driven/local-only policy, `.jev/preflight.json`, and observed allocation configuration. Plugin `simulator_udid`, `android_device`, `experimentalDriven` feed those environment variables; removing these settings breaks deployed configuration. `plugin/plugin.json`, `src/driven/project.ts`, `src/observed/allocation-config.ts`. |

**Conflict with removing old settings:** remove MobileBuildMCP/mobilecli execution and dependencies at accepted cutover, but preserve the bridge-owned reader for `.mobilebuildmcp/config.yaml` and existing plugin device settings. Removing the legacy file lookup invalidates currently valid scripts that omit `device.udid`; renaming the environment/settings does the same. A compatibility reader is configuration handling, not an old UI backend. Separate new Appium settings from the file's old vendor settings; do not pass the YAML to Appium. `CAPABILITIES_CONFIG` parsing silently falls back on errors upstream, so it must not replace bridge fail-closed profile validation.

## Changes required in phase specifications

1. Phase 2: specify optional profile selector names, project default location, applicability to each public route, capability allowlist and exact conflict/precedence rules. Preserve legacy device precedence above; reject profile platform/device conflicts before mutation. Keep ordinary installed/booted prerequisites and no automatic provisioning.
2. Phase 3: pin extension schema/version, owned-session lookup, XML/settings/overflow policy, role/placeholder/value mapping, fresh all-match rematching, replacement plus shown-value behavior, typed-text-safe responses/logging, explicit one-dispatch gesture sequences, coordinate provenance, capture capabilities/close side effects, native diagnostic support matrix, and parked observed transfer.
3. Phase 4: prove those contracts on the required simulator/emulator/physical Android phone, both corpora, two coordinate sizes, attach/capture no-app-mutation, secure/formatted/Unicode text, health/log attribution and lifecycle loss cases. Keep existing unsupported iOS modes and later physical-iPhone scope separate.

## Unresolved contract decisions and proof gaps

- Exact profile wire names and precedence against old environment/project defaults are not settled by choosing "optional profile plus project default." Recommend preserving every existing precedence rule and rejecting explicit profile identity conflicts.
- Freeze the approved public driver method/execute-command allowlist and extension result/error schema. Core does not export command wrappers or a native fencing receipt.
- Choose XML settings, completeness limits and state/field correspondence before recording golden Appium observations. Hint/password/duplicate-label parity remains unproven.
- Specify iOS clear/type acknowledgement behavior and Android foreground discovery/launcher resolution. Source support for methods does not prove restart, attach, capture or delete side effects.
- Define supported native health/log diagnoses per platform and required fence evidence; unavailable support remains unknown, not success.
- Current gesture convenience handlers' retry behavior and typed-value echoing are incompatible with bridge guarantees unless bypassed through the bounded extension or explicitly constrained. Live proof is still required for every claimed preserved behavior.
