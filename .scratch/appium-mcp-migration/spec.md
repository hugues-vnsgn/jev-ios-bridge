# Appium MCP migration specification

Status: ready-for-agent
Created: 2026-10-12
Source: [Confirmed migration plan](plan.md)
Implementation: not started
Implementation authorization: not granted
Delivery scope: the replacement release, phases 0 through 4 of the confirmed plan

The owner confirmed the design and explicitly deferred implementation. Publishing this spec authorizes documentation only. `ready-for-agent` describes specification readiness; an implementer must receive a separate instruction to begin.

## Problem Statement

A developer can use the bridge to verify iOS and Android apps, but device operation depends on two different integrations: MobileBuildMCP for iOS simulators and mobilecli's device agent for Android. Maintaining separate device layers complicates compatibility and recovery, and adding physical-iPhone automation would require another integration.

The developer needs a shared device layer without rewriting valid scenarios, losing driven or observed-action behavior, weakening device ownership, or changing what a verdict means. A migration that can tap and capture a screen but loses app logs, crash attribution, shown values, or screenshot coordinates would remove useful existing behavior. Changed accessibility evidence can also change Jev judgments even when the scenario and assertion renderer remain unchanged.

The replacement must establish compatibility before removing the old backends. A disconnected automation process or successful cleanup reply cannot justify returning a device to another run while native work may still act on it.

## Solution

Use one bridge-owned Appium MCP adapter for UI observation and input on the existing supported device categories. The host agent continues to use the bridge's CLI and MCP interfaces. The bridge continues to own scenarios, guards, Jev judgments, device admission and leases, recovery, evidence, and reports.

Deliver the replacement only after the selected v1.4.0 capabilities, both frozen assertion corpora through the production Appium observation path, and live acceptance on iOS simulators, Android emulators, and physical Android devices pass. Permit bounded native helpers for capabilities outside the proven public Appium interface. Keep uncertain devices quarantined until recorded evidence establishes that the run can no longer act on them.

Physical-iPhone enablement, allocation reclamation, and native performance measurement remain separate later milestones.

## Implementation Decisions

1. **Source base.** Start from released v1.4.0 source commit `0d3e54a9d1d80c1a9188c8c5e5717254e9a95994`. Preserve the original checkout's uncommitted changes in place. Reconcile the older main branch and its marketplace-only successor before eventual integration; neither is the implementation base.
2. **Baseline repairs.** Reproduce the five historically reported release-check failures on the selected base. Repair version expectations while retaining an independent package/tag consistency check, and repair the packaged documentation link. Commit these bounded repairs separately from the backend migration. Historical test results do not substitute for a fresh baseline.
3. **Delivery order.** Complete baseline repairs, then protocol feasibility, then configuration and ownership, then full adapter and mode compatibility, then live acceptance and cutover. Ownership controls precede effects. Feasibility must pass before full adapter construction. Driven scenarios, observed actions, and Android capture are replacement-release gates; reclamation is not.
4. **Production modules and composition.** Replace the device-driver composition with a shared Appium adapter and a private stdio MCP connection. Integrate it through the existing scenario service, CLI/MCP composition, capture flow, and the distinct observed-preparation and observed-action driver roles. Prefer the existing `DeviceDriver` contract and existing narrower roles; its internal shape may change while user-visible behavior remains compatible.
5. **Session ownership.** Create explicitly identified, bridge-owned Appium sessions for execution. Record the associated device, run or observed executor, allocation/action identity where applicable, process ownership, and unresolved operations. Every session-scoped request carries an explicit session ID. Shared sessions, remote servers, device farms, and transport fallback are outside this release.
6. **Protocol validation.** Validate the required server version, tool schemas, and every consumed result before relying on them. Cover creation IDs, accessibility XML envelopes, all matching elements, screenshot evidence, errors, and malformed responses. A human-readable success message is not a machine-validated outcome. Refuse incompatible schemas and invalid required data without guessing an ID or redispatching a mutation.
7. **Public extension.** Prefer upstream structured results. Where required IDs, results, or session inventory cannot otherwise be exposed reliably, permit a small, versioned bridge-owned extension through public `appium-mcp/core` interfaces. The extension has the same protocol and feasibility gates. Private upstream imports and an upstream fork are excluded, and a structured cleanup reply does not establish a fence.
8. **Frozen automation stack.** Phase 1 selects and records exact Appium MCP, Appium/base-driver, XCUITest, UiAutomator2, and WebDriverAgent versions, their resolved graph and integrity metadata, and the versions actually loaded. Freeze WDA runtime artifacts separately by version, architecture, hash, and relevant signing provenance. Uncontrolled latest-release downloads or newest-cache selection cannot alter the selected runtime. Inspected source versions are candidates, not approved integrations.
9. **Configuration and preflight.** Provide one validated project configuration for named profiles, device/app identities, platform capabilities, and startup, operation, and cleanup timeouts. Retain existing scenario defaults, launch options, device-selection options, and budgets. Reject profile/scenario conflicts before device mutation. Keep credentials outside tracked configuration. There is no backend-selection setting. Preserve ordinary scenarios' installed-app and already-booted-device requirements before Appium session creation; they do not gain implicit boot, provisioning, or data reset. Observed allocation retains its explicitly authorized boot/install preparation. Document SDK, Java, and Xcode prerequisites.
10. **Accessibility normalization.** Normalize platform XML into the bridge's roles, identifiers, labels, values, visibility, frames, and snapshot-scoped references. Keep normalization and locator handling separate from Jev judgment. Preserve production observation limits, field meanings, and overflow refusal. Record observation-shape and stack provenance truthfully when the evidence path changes.
11. **Target resolution.** Resolve exactly one eligible target after guards pass. Refuse missing or ambiguous targets. Refresh and rematch expired or stale references before dispatch. Appium's first-match lookup is insufficient. MobileBuildMCP's vendor-specific tap-alias proof cannot authorize Appium aliases; any equivalence used to preserve valid selectors requires its own evidence.
12. **Actions and settling.** Preserve tap, replacement text, swipe, and supported driven back/scroll behavior and reported action paths. Serialize device commands under existing time and cancellation budgets. Require terminal execution evidence and bound screen-settling waits. Record the last capture as still changing when the settle limit expires. A completed command does not prove the intended app outcome; guards and checkpoints retain that responsibility.
13. **Uncertain effects.** Do not automatically repeat taps, typing, creation, or other mutations after a lost or uncertain response. Cancellation durably closes new dispatch; an already-authorized outstanding command remains terminally accounted for or uncertain until fenced. Late replies cannot restart execution or revise an immutable outcome. Recovery of ownership does not resume or replay the interrupted scenario.
14. **Shown values.** Read a field's displayed value after replacement from fresh evidence. Preserve Android shown-value events and `typedFields` report semantics. Echoed input or a successful typing reply does not establish the shown value. A legitimate transformation between typed and shown values does not itself fail the action.
15. **Screenshots and coordinates.** Retain snapshot/screenshot dimensions and their evidence relationship. Driven hand-backs refresh the screen before dispatch. Android `tapAt` uses whole-pixel coordinates of the paused screenshot, validates bounds, converts to device coordinates, and refuses stale, rotated, or unknown geometry before input. Prove conversion on at least two device sizes. Preserve explicit current refusals for iOS attach and iOS coordinate taps; this spec does not enable them.
16. **Driver diagnostics.** Preserve live app output, headless `logs`, log-pane behavior, app exit and supported ANR attribution, bounded late-event handling, and truthful unknown health status when observation is lost. Expected bridge shutdown is not a crash. Keep preparation identity and warnings and meaningful reference-refresh metrics; do not manufacture MobileBuildMCP expiry counts or relabel automation timing as app performance.
17. **Android capture.** Preserve its public options, exit codes, named element fields, and production `--jev` projection. Capture settles the current screen under ownership without restarting or stopping the app, taking a screenshot, requiring a Jev key, or constructing a judgment request. Route it through the same Appium composition and admission authority.
18. **One admission authority.** Extend v1.4.0's per-user SQLite admission authority to Android through an explicit offline schema migration. Its existing iOS-simulator and UUID constraints must become validated canonical platform/device identities. Resolve emulator AVD aliases and changing serials to one stable identity. Keep transactions responsible for authorization and durable publication; perform device work outside transactions. Changing home, project, working directory, or temporary-directory settings must not create another production authority.
19. **Migration preservation.** Preserve historical action identities and digests, requests, immutable outcomes, tombstones, quarantine, retained capacity, exclusions, migration receipts, and unresolved native-owner claims. Preserve migration source evidence and fail closed on partial, missing, corrupt, or uncertain authority. A missing old process, receipt, or temporary guard is not evidence of native settlement. Do not introduce an Appium-specific ownership store or a fallback store.
20. **Admission and lease distinction.** Admission authorizes device work; it does not prove native release. Release the device lease only when dispatch authority is durably closed, every issued command is terminal or covered by a proven fence, and every owned native automation component that could still act is verified stopped or unable to accept further commands. Record owned identities, command dispositions, fence evidence, and cleanup results before release. Successful session deletion, an empty process-local list, or MCP process exit alone is insufficient.
21. **Lost-session recovery.** Reconcile an owned session where reliable evidence permits it. Lost creation without a returned session ID remains quarantined until the same lease-release predicate is established. Retain quarantine for an unreachable device or incomplete component evidence. Provide diagnosis and explicit recovery; safe cleanup leaves uncertain execution inconclusive and cannot rewrite a committed observed outcome.
22. **Coordination limits.** Serialize all updated entry points through shared admission, including scripted/observed competition and Android aliases. Old bridge binaries, other OS users, and external device tools require operational exclusivity as stated by ADR-0008. Refuse foreign automation where detectable and never stop it as bridge cleanup. Do not claim that the new database automatically coordinates tools that do not participate.
23. **Observed-action contract.** Preserve the experimental iOS-simulator-only, single-authored-tap scope, visible before/after predicates, and distinct observed outcomes. Preserve the existing CLI/MCP operation pairs, enablement behavior, immutable request/allocation/action binding, one executor, identical-request retrieval, changed-request conflict refusal, authoritative committed publication, cancellation, retirement, and evidence retrieval. These operations remain independent of Jev credentials, SDK construction, and judgments.
24. **Allocation compatibility.** Preserve supplied inventory and bounded fresh creation, immutable app artifact/provenance checks, reservation before effects, readiness, parked ownership, and transfer to a separate action executor. Fresh simulator creation keeps explicit device type/runtime, durable intent and host-wide guard, capacity reservation, and durable binding of the returned identity before preparation. Unknown fresh-simulator creation retains capacity and blocks new updated iOS admissions while the device identity remains unresolved, without inferred ownership or an automatic retry. Preserve the current eight-allocation capacity and retention policy; session cleanup does not release retained allocation capacity.
25. **Native-helper boundary.** All UI observation and input use the Appium adapter. Prefer proven public Appium/core capabilities. Permit only bounded helpers for app logs and crash detection, evidenced fencing of recorded owned automation, optional nonfatal simulator presentation, and the existing bounded simulator-creation exception. Keep helpers under ownership, deadlines, and the driver lifecycle. Log/health observers are read-only. Normal cleanup cannot erase phones, delete allocated simulators, or use AXe as an alternate input path.
26. **Privacy and evidence.** Disable Appium's optional AI features and pass device children only the environment they need, excluding Jev credentials. Filter vendor responses and errors before run logs because text-entry replies may echo supplied values. Preserve current value masking, local screenshot/evidence handling, watch access protection, and the established data-handling contract. Log unavailable sources explicitly rather than presenting them as empty output. Add truthful backend/version provenance without credentials or raw supplied values.
27. **Assertion semantics.** Preserve the pinned production judge, 0.9/0.1 bounds, false-wins checkpoint precedence, and single judgment without re-asking. Uncertainty remains visible and cannot become a pass through cleanup or retries. Changed evidence must pass both corpus gates through the new normalization path before cutover, even if the final renderer's source is unchanged.
28. **Corpus protocol.** Preserve frozen case identities, claims, truth labels, and denominators. Obtain matching Appium XML and screenshots for the same screen states, then use the production Appium normalizer, production observation renderer, and pinned production Jev judge. Preregister state correspondence and evaluation before querying. Record exact observations/requests and hashes, raw evidence, stack provenance, and results. Recover the Android corpus with history/provenance. Changed or unreproducible states block evaluation until reconciliation is explicitly agreed; do not silently relabel, replace, or remove them.
29. **Release compatibility.** Preserve the frozen script, public transport, verdict, reason-code/role, report, and evidence-layout contracts, and retain supported experimental capabilities. Demonstrating an unsupported backend capability does not permit rejection of a previously valid stable script. Any required frozen-contract break uses the repository's separate major-version process; this spec supplies no permission for that break.
30. **Cutover.** After all replacement-release gates pass, remove old production execution paths, runtime dependencies, AXe input, and settings/setup references used solely by the old vendors. Audit every public route and all driver factory roles. Retain history/migration readers and only native helpers within the agreed boundary. Apply ADR-0010/0011 and update the superseded provider and AXe portions of earlier ADRs at actual cutover; preserve bounded creation constraints. Native studies remain research and their evidence and unresolved exclusions survive.

## Testing Decisions

1. **Observable behavior.** A good test checks the public outcome, exact external requests, authoritative stored state, or emitted evidence. It does not mirror parser implementation, assert private call order without an authorization consequence, or treat a mocked deletion reply as proof that native work stopped.
2. **Highest seam.** Exercise public CLI/MCP operations and their existing services with the real Appium adapter, admission authority, scenario/observed execution, evidence, and reports. Substitute a controllable private MCP process at the external device-provider boundary. Reuse existing judge injection for deterministic offline tests and existing native-command fixtures for helper behavior. Focus new fault control at this boundary rather than introduce separate product test APIs throughout the bridge. This carries forward the confirmed plan's adapter/controllable-process approach.
3. **Prior art.** Extend the stable contract goldens, service lifecycle and hand-back suites, observed CLI/MCP and cross-process race/crash fixtures, admission migration and authorization tests, and existing driver/observation and log-pane tests. Preserve their behavioral assertions while replacing vendor-specific fixture responses. Use a small fixture-level normalizer check only where the public result cannot diagnose a malformed capture precisely.
4. **End-to-end proof.** Through both public transports, run a representative existing iOS script and an Android script that launch with authored options, observe, resolve a unique target, tap, replace text, wait, and judge a checkpoint. Assert compatible exit/reply/report semantics, visible evidence and shown-value reporting, one authorized input attempt, owned cleanup, and a safe subsequent run. Execute driven hand-back and observed prepare/start/retrieve cases through the same composition so a scripted-only adapter cannot satisfy the problem statement.
5. **Protocol fixtures.** Freeze request/result fixtures for the selected runtime: server identity, tool schemas, explicit session IDs, creation IDs, XML, all-match lookup, actions, screenshot artifacts, and deletion/error responses. Test malformed, missing, inconsistent, and changed fields. Assert no inferred identity, unvalidated success, implicit session, or mutation retry reaches the wire. Test the public extension against the same contracts if used.
6. **Configuration and environment.** Assert invalid profile/device/app/timeout conflicts produce the existing safe public failure before effects. Assert existing platform defaults, iOS launch arguments, Android activity/intent extras, and budget meanings reach the actual Appium requests unchanged in meaning. An ordinary scenario on a stopped device must retain its refusal without an implicit boot/session mutation; observed allocation may perform only its authorized preparation. Assert optional AI is disabled, the child environment is restricted, credentials are absent, and typed values are read once.
7. **Stack identity.** Assert the installation/selection record contains exact resolved driver versions and integrity metadata, actual-loaded versions, and WDA artifact architecture/hash/provenance. A mismatched runtime or schema is refused before session creation. Prove that a different newest cache entry or upstream latest artifact cannot replace the selected WDA artifact. Pin these public selection and provenance contracts to the chosen Phase 1 stack.
8. **XML and observation.** Use captured fixtures covering roles, duplicate labels, identifiers, visibility, disabled/password fields, values/placeholders, frames, scrollability, and changing screens. Assert the resulting guards, selectors, rendered observation, and overflow behavior through the adapter/service. Pin exact production observation text or hashes for representative states. Ensure old vendor alias authorization is not inherited without an Appium-specific proof.
9. **Input safety.** Missing/ambiguous targets, stale references, changed guards, expired captures, and invalid coordinate geometry must dispatch no input. A permitted refresh may rematch once under policy but cannot repeat an uncertain mutation. Pin the permitted wire action arguments and resulting action-path evidence for tap, replacement text, swipe, back, scroll, and Android coordinate taps.
10. **Settling and coordinates.** Assert bounded settling and the still-changing mark. Assert screenshot dimensions and orientation correspond to the capture used for a paused answer, points remain within bounds, and converted coordinates match at least two device sizes. A stale/rotated/unknown screenshot returns the documented refusal or fresh hand-back without a tap. Verify this with live device evidence as well as fixtures.
11. **Shown values.** Supply a field whose displayed value transforms the typed input. Assert the adapter reads the fresh shown value, the Android action/report contracts contain the proper masked evidence, and the mismatch itself does not fail execution. A vendor echo or typing acknowledgment alone must not populate shown-value evidence.
12. **App logs and health.** Assert app prints and platform log output reach the pane, headless attachment, and step tails with current app filtering and supplied-value masking. Assert empty output differs from an unavailable source. Deliberate app exit and supported ANR retain their reason codes; expected shutdown, old events, lost streams, and automation-agent failure do not manufacture an app diagnosis. Cover bounded late-event attribution and owned stream cleanup with live checks for each claimed capability.
13. **Capture contract.** Through the Android public command, assert compatible flags, exit codes, element fields, and `--jev` output. Assert no app launch/reset/stop, screenshot request, Jev request, or credential requirement. Assert capture still participates in shared admission and refuses a device owned by another updated entry point.
14. **Driven contract.** Verify experimental enablement, preflight/local-only policy, budgets, decision/search/hand-back evidence, pause ownership, and `resolve_step`. Prove that refreshed evidence prevents a late answer from acting on a changed screen. Pin preserved refusal of unsupported iOS attach/coordinate requests before input.
15. **Observed public contract.** Through CLI and MCP, assert every preserved operation's inputs/replies and committed state. Identical requests return the same immutable result without more backend calls; changed requests conflict without device or authoritative-state mutation; concurrent requests bind one executor. Verify key-free operation and zero Jev requests, parked preparation transfer, and retrieval after reply/export loss.
16. **Allocation state.** Pin durable reservation, immutable artifact identity, explicit creation intent, host-wide creation guard, returned device binding, readiness, parked ownership, action binding, retained capacity, and retirement/outcome publication. Assert unknown fresh-simulator creation retains capacity and blocks new updated iOS admissions while its identity is unresolved, and no retry infers ownership from a name. Supplied inventory remains explicit and is never an automatic uncertainty fallback. Normal cleanup must issue no delete, erase, or prohibited shutdown operation.
17. **Migration and shared identity.** Test offline migration from the selected-base schema and declared historical sources, including Android leases and unresolved native exclusions. Pin the canonical identity and logical preserved records, immutable outcome/digest/tombstone history, receipts, reservations, and quarantine. Crash/partial/corrupt migrations fail closed without alternate authority. Cross-process tests using working-directory/project/home/temp aliases must share production authority, and AVD/serial aliases must exclude each other.
18. **Cancellation, lost replies, and fencing.** Control before/after-dispatch barriers, late replies, creation-response loss, action-response loss, MCP failure, and device disconnection. Pin durable authorization/cancellation and pending/terminal/uncertain dispositions and the exact permitted mutation count. A later reply cannot add input or revise an immutable outcome. Assert lease retention until all three release conditions are recorded, then assert another run can safely acquire the device. Cleanup success or an empty list without native evidence must retain quarantine.
19. **Native-helper boundaries.** Assert read-only observer commands, owned process/session identities for fencing, exact bounded creation arguments, presentation controls, and deadlines. No helper may become a UI observation/input fallback, stop foreign automation, erase a phone, or delete retained allocations. Prefer existing native-command fixtures; require live evidence for a helper's native fence rather than infer it from fixture termination.
20. **Frozen public contracts.** Retain goldens for valid scripts, roles/reasons, CLI/MCP commands/options/replies, exit codes including signals, report fields, evidence names/envelope/events, Android capture, and observed operations. For each new or changed wire/persistence behavior in the implementation decisions, pin the resulting request, safe reply, logical durable record, or provenance field in the corresponding cases above. Review additive golden changes; changing expectations cannot authorize a frozen semantic break.
21. **Firm Phase 1 gate.** Before building the full adapter, produce a go/no-go report on both an iOS simulator and an Android emulator. Include pinned fixtures, a real observe/action/check round trip, validated result parsing, cancellation, late replies, lost creation/action responses, process failure, native cleanup evidence, and quarantine/reconciliation results. Every required item must pass. An unproven release mechanism stops production integration; unreachable cases may remain safely quarantined but cannot be presented as reclaimed devices.
22. **Jev corpus gates.** Use matching Appium XML/screenshots for frozen states through the production normalizer, renderer, and pinned judge. Judge each screen once without re-asking. iOS must give zero confidently wrong answers and at most three uncertain claims across 24 screens/48 claims. Android must give zero confidently wrong answers across 10 screens/31 claims. Preserve truth labels and denominators and preregister correspondence before calls. Old archived text alone does not satisfy these gates.
23. **Live replacement acceptance.** Run the preserved mode/capability matrix in its existing platform scope on an iOS simulator, Android emulator, and physical Android phone. Cover launch/options, captures, taps/text/gestures, checkpoint outcomes, ambiguity/staleness, keyboard/changing screens, logs, health, shown values, coordinate geometry, competing updated runs, cancellation, process loss, disconnects, and safe cleanup. Demonstrate at least 20 independent scenario/session cycles per replacement device category without accumulating owned sessions. Record model, OS/toolchain, stack, app build, commands, outcomes, and evidence references. Unavailable hardware remains untested and blocks its replacement-release acceptance.
24. **Outstanding baseline evidence.** Execute the five unfinished v1.4.0 live simulator acceptance cases, or preserve their requirements in an explicitly mapped replacement matrix. The release tag and historical host tests cannot mark those live cases passed. Observed allocation retention remains in force; the later 20 allocation/action/reclamation cycles under the eight-allocation limit are not substitutes for this release's compatibility cases.
25. **Cutover and packaging.** Audit the packaged production composition and public routes for old vendor execution/dependencies and AXe input, while allowing retained historical evidence and migration readers. Complete typecheck, host tests, build, stable-contract checks, clean-install/plugin checks, packaged documentation/link checks, and a real quickstart on the resulting artifact. ## Out of Scope

- Starting implementation under this documentation request, including the Phase 1 tracer or baseline code repairs.
- Physical-iPhone enablement. It remains a later gate for signing, the complete driver capability matrix, ownership, recovery, and live acceptance.
- Expanding observed actions beyond their existing single-tap iOS-simulator scope, enabling currently unsupported iOS attach/coordinate combinations, or declaring experimental modes stable.
- Allocation reclamation, deletion, pooling, automatic retention/reuse policies, or release of retained capacity. The later lifecycle must preserve action records and tombstones, durably claim cleanup, perform device work outside transactions, verify completion, and only then release capacity.
- General simulator/emulator/device provisioning, runtime downloads, app building, phone reset/erase, or new installation workflows beyond existing observed-allocation compatibility.
- Remote/shared Appium sessions, device farms, another UI backend, runtime fallback to MobileBuildMCP/mobilecli/AXe, an upstream fork, or private upstream imports.
- Native performance runners and benchmark/profiling APIs. Later measurements require device/build provenance and comparable baselines; automation duration is not such a measurement.
- A production native-owner guarantee derived from historical research, or automatic coordination with older binaries, other OS users, and external tools.
- Changing frozen assertion semantics, changing the pinned Jev model, re-asking uncertain judgments, weakening corpus denominators, or granting permission for a major-version contract break.
- Publishing a release, pushing or merging changes, or selecting a final release version under this spec-writing task.
