# jev-ios-bridge 1.3.1

Fixes from the first live trial of driven mode on a real app, and a README section on what a check costs. Driven mode is still experimental and off unless you turn it on. Version 1 scripts run as they did in 1.3.0.

## Install

With Claude Code:

```sh
claude plugin marketplace add hugues-vnsgn/jev-ios-bridge
claude plugin install jev-ios-bridge@jev-ios-bridge
```

Already installed? Run `claude plugin marketplace update jev-ios-bridge`, then `claude plugin update jev-ios-bridge@jev-ios-bridge`, and restart Claude Code. Your settings stay as they were.

For the command line, Codex, or CI:

```sh
gh release download v1.3.1 -R hugues-vnsgn/jev-ios-bridge -p 'jev-ios-bridge-1.3.1.tgz'
npm install ./jev-ios-bridge-1.3.1.tgz
```

You need macOS, Node 24 or later, and a TypeSafe API key. For iOS, you need Xcode. For Android, you need the Android SDK's `adb` and a device on Android 12 (API 31) or later. Start with the [quickstart](https://github.com/hugues-vnsgn/jev-ios-bridge/blob/v1.3.1/docs/guide/01-quickstart.md), and see the [driven steps guide](https://github.com/hugues-vnsgn/jev-ios-bridge/blob/v1.3.1/docs/guide/13-driven-steps.md) for driven mode.

## What's fixed

- **Scrolling up on iOS.** Jev's search for an off-screen target scrolls down, then up. On iOS, the scroll up never moved a list that sits under a fixed header, such as a search bar, because the swipe started on the header. Scrolls now use a stroke centred in the list, as on Android. On a screen with no scrollable list, the fallback scrolled the wrong way; it now scrolls the way it's asked. A version 1 script's `swipe` is unchanged.
- **Screens that are still loading.** When Jev finds nothing that fits, the bridge now waits a second and looks at the screen again before scrolling to search. If the screen changed by itself, such as a launch screen that finished loading or a list that filled in, Jev decides again on the new screen. A step gets at most 3 such looks. Before, a run's first decision often landed on the app's launch screen.
- **Write buttons in read-only steps.** In a step whose effect is `none`, the bridge no longer carries out a pick of a control labelled Approve, Reject, Send, Submit, Confirm, Save, Publish or Post. The step goes to Claude as `RISKY_ACTION`. A `test_write` step is unchanged.
- **Hand-backs name the paused screen's elements.** After a search scroll that changed nothing, a hand-back could list Jev's picks by references from an earlier capture of the same screen.

## What a check costs

The README has a new section, [what a check costs](https://github.com/hugues-vnsgn/jev-ios-bridge/blob/v1.3.1/README.md#what-a-check-costs). Jev costs $0.042 per million input tokens, and output is free, so a whole driven run costs about $0.002 in Jev tokens. Claude is most of the bill: in the first live trial, driven runs cost $1.10–$1.66 of Claude time per short flow, against about $0.60 for Claude driving the simulator directly. Bringing Claude's side down is the next piece of work.

## Checked before release

- **Tests:** 929 pass, locally and in CI on the release commit, up from 920. New ones pin the iOS scroll commands (and that a version 1 `swipe` is unchanged), the look at a screen that changed by itself, the write words, and the search through the real Android driver against a fake device.
- **Review:** the pull request's review found that a screen unchanged after the look was searched from an older capture, which Android's driver refuses, so the search never scrolled there. Fixed before release, with a regression test.
- **Where the fixes came from:** the first live trial, two read-only flows on a real app's iOS build. Re-run on the same screen with the fixed build, all three of the search's scrolls up moved the list; before, its scroll up left the list where it was.
- **Live checks on the release package,** on an iOS simulator with a test copy of ReadMe, with a script answering the pauses:
  - A version 1 script **passed**, with the same 1,498 tokens to Jev as in 1.3.0.
  - Jev opened a book by itself and the run **passed** (tap at 0.96, done at 0.96).
  - Claude's tap after a pause was carried out on a fresh capture, and the run **passed**. With another app brought to the front during the pause, the tap was **not** carried out, and the step paused again with `SCREEN_CHANGED`.
  - Scrolling a three-page list to its last book and back **passed**. On the way back, Jev scrolled up twice by itself and ended the step.
  - With driven mode off, a driven script was refused with `DRIVEN_NOT_ENABLED`.
- **Not checked live:** the look at a launch screen (the test app has none) and Android. Tests cover both.
- **The packages:** the plugin zip, installed the way Claude Code installs it, and the tarball, installed with `npm install`, both print `1.3.1`. `claude plugin validate` passes the plugin and its marketplace entry.
- **Records:** every run is in [release-checks.md](https://github.com/hugues-vnsgn/jev-ios-bridge/blob/v1.3.1/spikes/benchmarks/results/v1.3.1/release-checks.md).
