# v0.1.0 prerelease

Experimental prerelease for guarded iOS scripts and recorded assertion evidence.

This first prerelease executes complete, guarded iOS scripts through MobileBuildMCP and uses TypeSafe Jev to judge screen assertions. Claude Code submits one script and reads the recorded report. Jev does not choose actions.

## Included

- CLI and stdio MCP server with `start_scenario`, `get_report`, and `cancel_run`.
- `/test-ios` skill for authoring and submitting complete scripts.
- Taps, full-field text replacement, directional swipes, bounded waits, and assertion checkpoints.
- Private JSONL evidence, local screenshots, bounded reports, and a token-protected localhost watch page.
- Conservative missing-target, ambiguity, uncertainty, cancellation, and cleanup handling.

## Install

Download `jev-ios-bridge-0.1.0.tgz` from this GitHub release and install it in the consuming project:

```sh
npm install /path/to/jev-ios-bridge-0.1.0.tgz
node node_modules/jev-ios-bridge/dist/cli.js --version
```

Use Node 24 or later, macOS with Xcode, an already booted dedicated simulator, and an installed app. Live tests used Xcode 26.4.1 (17E202), iOS 26.4 on an iPhone 17 Pro Max simulator, and Node 26.8.1; CI also passed on Node 24. Load a private `TYPESAFE_API_KEY` by environment or Node's `--env-file`. The pinned device dependency is `mobilebuildmcp@2.7.1`. See the v0.1.0 usage notes in the repository history (`docs/usage.md` at tag v0.1.0) for scripts, MCP registration, and skill installation. There is no npm registry release.

## Evidence

The owner-approved, frozen assertion experiment used 24 fresh screens with one true and one false claim per screen. At fixed 0.9/0.1 probability bounds, 22/24 true and 23/24 false claims were confidently correct, with zero confidently wrong answers. Three judgments were uncertain. Twelve real scripts matched six expected passes and six expected assertion failures. Three fault probes stopped inconclusively without device actions or Jev requests.

Typecheck, 157 tests, build, and Node 24 CI passed. The installed Claude Code submission/report path passed. A separate blind test identified a planted total-calculation bug from its failed report and app source. Full benchmark scripts passed Weather and Contacts. Reminders reached the correct observed state but returned inconclusive because its count claim scored 0.87, below the fixed 0.9 bound. The two verified comparisons had lower model-cost estimates and longer host elapsed time; there was no verified Reminders baseline. [Measurements](../research/scripted-benchmarks.md) include all attempts and scope differences. These small exploratory tests do not establish a universal error rate.

All three earlier autonomous-action experiments failed their original gates and remain preserved. This release uses the subsequently accepted scripted design; it makes no autonomous-navigation claim.

## Limits

- Simulator UI automation only. Claude Code is tested; Codex support is best effort.
- Build, install, seed, and reset are operator tasks. Preparation restarts the app; restored UI state may vary.
- English screen evidence and printable US-keyboard typing. Keyboard state can affect casing and replacement; post-action guards must check the result.
- At most 100 scripted steps, default whole-run limit 300 seconds, and bounded waits up to 60 seconds. Unexpected screens and uncertain judgments stop inconclusively.
- Unknown command acknowledgements may retain the device lock for manual recovery.
- Observed screen text and assertion claims go to TypeSafe. The host receives the script and report. Exact supplied values and credentials are redacted from textual evidence; screenshots stay local and are not redacted.
- Real transient-wait corpus coverage is deferred. Automatic hooks, CI operation, real iPhone UI automation, and host escalation are outside this version.
- Initial script-authoring cost was not metered. Prepared execution measurements alone cannot support total-savings or break-even claims.

See the [evidence and release tracker](../../.scratch/jev-ios-bridge/map.md) for preserved results, unsuccessful attempts, and verification details.
