# Durable admission coordinates updated iOS bridge entry points

The observed-action journal can retain uncertainty while a legacy device lease reclaims a dead process's device. Its status methods can also quarantine active work, and multi-file finalization can leave a completed-looking result after failed cleanup. All updated iOS entry points will share device admission, with non-mutating status, immutable declared action identities and transactional terminal/disposition publication. [Decision and reproduced host evidence](../../.scratch/observed-integration/evidence/admission-decision.md).

Use Node's built-in SQLite through a private adapter under the per-user Application Support directory. Transactions authorize ownership and dispatch; device work stays outside transactions. Node 24.0.0 supports the selected API but labels it active development, so minimum-runtime verification is mandatory. Explicit offline migration preserves old uncertainty and replay history before activation. The alternative of extending independent filesystem claims leaves cross-runner and multi-file authority gaps.

Device admission does not weaken the domain's Device lease invariant or prove native release. Quarantine is monotonic. Old binaries, other OS users and external device tools require operational exclusivity. No updated entry may create an alternate store when authority is missing, corrupt or uncertain. Implementation and acceptance follow the [rollout specification](../../.scratch/observed-integration/spec.md); this ADR records the decision, not a completed guarantee.
