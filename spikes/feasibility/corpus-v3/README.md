# Checkpoint feasibility corpus

`corpus.json` contains ten rewritten tuning questions on byte-for-byte copies of the first corpus's captures, plus 20 fresh held-out captures: Weather 5, Contacts 8, Reminders 3, and Diagnostic App 4. The old tuning cases are disclosed development data. The new held-out `screenHash` values are distinct from one another and from both previous held-out partitions. Each case has paired compact/full MobileBuildMCP JSON, a screenshot, and SHA-256 hashes for all three assets. Labels remain proposals until the owner reviews and approves this exact corpus and manifest. No v3 Jev request has been made.

Every case asks for one visible checkpoint state. Scenario values appear only in cases that type: Mira's first name, the Oslo or Ada Birch search, Iris's replacement email, or the Pack batteries note. Future checkpoint values do not enter navigation cases. A reached goal can still have a false assertion; Weather's mph claim, Iris's old-email claim, the Reminders missing-note claim, and the Diagnostic App's $5 claim exercise that distinction. No captured screen warrants `wait`, so transient-wait behavior remains unverified.

The Weather app is Sentry's deterministic mock fixture. Its location picker was searched for Oslo; the captured main Weather button then reads Oslo. The wind setting changes from mph to m/s on later captures. The mock fixture and pinned device commands are documented in [benchmark preparation](../../benchmarks/README.md).

Contacts has two synthetic Iris Moss cards. The Summit card initially held `iris.old@example.test`; the Harbor card did not. Company names appear in screenshots but not in the text snapshot, so both same-name list taps are valid inspections and the scored target is identified by the unique old email. Six synthetic phone rows push the email below the edit viewport. The recorded upward finger swipe reveals it, `type-text --replace-existing` enters `iris.new@example.test`, and the saved card later shows that new address. Ada Birch was never created; its search was captured only after MobileBuildMCP reported the UI settled and the screen explicitly said no results.

Reminders uses a new synthetic Pack batteries item. Its three scored screens show an empty foreground Notes field, `Bring charger` typed but unsaved, and a saved list row whose label includes the note. `preflight/` preserves rejected routes: Priority had no tap action, tapping September 25 did not change the selected date, and the List chooser exposed no tap target. The abandoned expanded-calendar case also exceeded Jev's request byte budget in full observation. None is scored. The Diagnostic App was rebuilt with launch-screen metadata after the first version's taps landed above its letterboxed controls. The scored captures show Apple selected, then Apple and Bread, then an Order complete confirmation that visibly totals $3 instead of the intended $5.
